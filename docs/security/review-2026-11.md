# Security review: November 2026 (Phase 7)

**Scope:** API (FastAPI), worker, agent runtime, BFF and web app, billing, deployment configuration.
**Method:**
- Automated: static analysis, dependency audits and the security test suites.
- Manual: a review against an OWASP ASVS L2-style checklist.

**This is an internal review by the build team, not an independent penetration test.** An external test before launch is recommended (see "Open items").

## Findings
| ID | Severity | Finding | Status |
|---|---|---|---|
| F-01 | Medium | BI built `SELECT * FROM {name}` with a dataset name coming from model output. The GN7T read-only guard blocked writes, but a crafted name could read other tables in the same tenant's warehouse. | **Fixed.** Only plain identifiers are accepted, and they are quoted (`select_all`). Tested with injection strings. |
| F-02 | Medium | The web app sent no security headers (no CSP, no framing protection). | **Fixed:** CSP (`object-src 'none'`, `frame-ancestors 'none'`, `base-uri`/`form-action 'self'`, connections only to self and Paddle), `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. HSTS is set at Caddy. Residual: `script-src 'unsafe-inline'` (see R-29). |
| F-03 | Low | API responses had no `nosniff`, framing or no-store headers. | **Fixed:** set on every response by the middleware. |
| F-04 | Medium | No request body limits, so a large body (including to the public Paddle webhook) could exhaust memory. | **Fixed:** 1 MB, or 25 MB for document uploads, enforced by declared length and by counting chunked bodies (413). Caddy enforces the same limit at the edge. |
| F-05 | Low | Uvicorn trusted `X-Forwarded-For` from any address (`*`), so client IPs, and with them rate limits and audit IPs, could be spoofed if the API were reachable directly. | **Fixed:** trusted proxies come from `FORWARDED_ALLOW_IPS` (Caddy's network in production), and the API port isn't published. |
| F-06 | Low | The OpenAPI schema was public in production. | **Fixed:** disabled in production, as `/docs` already was. |
| F-07 | Info | Agent artifacts couldn't be downloaded at all. Serving them is a stored-XSS risk, since SVG and Markdown are written by models. | **Fixed:** `GET /v1/artifacts/{id}` is org-scoped and sends `nosniff`, a `default-src 'none'; sandbox` CSP, and `attachment` unless the file is an image. Tested with an SVG containing a script. |
| F-08 | Info | Hard-coded fixture secrets (fixture Paddle secret, eval password). | **Accepted:** fixture modes only; production refuses to start in them. |
| F-09 | Info | `assert` used for internal invariants (bandit B101). | **Accepted:** no authorisation decision depends on an assert. Images never run Python with `-O`. |
| F-10 | Info | `try/except/pass` around best-effort Redis wake-ups. | **Accepted:** the database is the source of truth and workers also poll. |

## Controls verified (ASVS-style)
- **Authentication:**
  - Argon2id password hashes.
  - Short-lived access JWTs; rotating refresh tokens with reuse detection that revokes the session.
  - Lockout and rate limits on login.
  - httpOnly cookies through the BFF (access `SameSite=Lax`, refresh `SameSite=Strict` and scoped to `/api`).
  - Origin checks on cookie-authenticated writes.
- **Access control:**
  - PostgreSQL row-level security on every organisation table, with fail-fast if the API role could bypass it.
  - Explicit organisation filters as well, and 404 (never 403) for other tenants' ids.
  - RBAC checks on every route.
  - Super-admin re-checked on the server for each request.
  - Approval-gated tools run under the approver's current authority.
- **Input and output:**
  - Pydantic validation everywhere.
  - SSRF guard (public addresses only, re-checked at connect time, no redirects).
  - Markdown rendered without raw HTML.
  - Agent output treated as untrusted in prompts (`<untrusted>` blocks) and when served.
- **Secrets:**
  - Provider keys and connection secrets are envelope-encrypted with additional authenticated data bound to the owner.
  - The API only returns the last 4 characters.
  - No secrets in logs; logs never include request bodies.
- **Payments:**
  - The server creates every checkout.
  - Signed Paddle webhooks are the only source of truth, with constant-time comparison, a timestamp window and idempotent processing.
  - Card data never touches AgentFirm.
- **Auditing:** an append-only audit log for security-relevant actions, admin changes, approvals, billing and credits.

## Open items before launch
- An **external penetration test** against the deployed staging stack.
- **R-29:** CSP `script-src 'unsafe-inline'`. It is needed for Next.js partial-prerender inline scripts, which can't carry per-request nonces in static shells. Revisit when Next supports hashes for PPR, or nonce the dynamic routes.
- **R-15/R-21:** DNS rebinding between the SSRF check and the connection. Route agent egress through a filtering proxy.
- Enable **2FA for super-admins** (not built). In the meantime, restrict `/admin` by IP at Caddy (see the deploy guide).
